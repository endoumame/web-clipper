# web-clipper 新機能提案 - 2026-05-04

## エグゼクティブサマリー

前回提案（2026-04-01）から AI 自動タグ付けとハイライト・アノテーション機能が実装完了した。2026 年 5 月現在、Readwise Reader の Ghostreader Chat やセマンティック検索が競合の標準になりつつある。本提案では、記事とのチャット機能・セマンティック検索・ブラウザ拡張を軸に 8 つの機能を提案する。

## 現状の機能セット

- 記事クリッピング: URL からメタデータ（OGP、タイトル、説明文）・本文（Markdown）を自動抽出し保存
- AI 要約生成: Cloudflare AI（llama-3.1-8b-instruct）による記事要約（バックグラウンド実行）
- AI 自動タグ付け: クリッピング時に既存タグプールから最適タグを自動提案・適用（最大 5 件）
- ハイライト・アノテーション: テキスト選択によるハイライト保存、5 色カラーコーディング、ハイライト別メモ
- タグ管理: カスタムタグの CRUD、記事数カウント、多対多リレーション
- 検索・フィルタ: タイトル/説明文の全文検索、ソース/タグ/既読状態フィルタ、カーソルベースページネーション
- ソース自動分類: Twitter、Qiita、Zenn、GitHub 等 11 種のソースを URL から自動判定
- 認証: ユーザー名/パスワード + GitHub OAuth、Cookie ベースセッション管理（7 日有効期限）
- UI/UX: ダーク/ライトモード、View Transitions API、デバウンス検索、Markdown レンダリング
- API ドキュメント: OpenAPI 3.0.0 仕様 + Scalar UI による API リファレンス

### 2026 年のトレンド変化

1. AI チャット型対話が標準化: 単方向の要約生成から、記事との双方向チャットへ進化している。Readwise Ghostreader Chat が牽引し、文脈理解型 AI が差別化要因になった
2. セマンティック検索の普及: キーワード一致ではなく、意味的な類似性に基づく検索が求められている。Remio の AI スマート検索や Auto Web Clipper のセマンティック分類が実証済みである
3. BYOM（Bring Your Own Model）が標準期待: Obsidian は Ollama・OpenRouter・Claude・Gemini に対応している。ユーザーが AI プロバイダーを選択できることが当然視されつつある
4. ブラウザ拡張は引き続き必須: 全主要競合が提供しており、ワンクリック保存は UX の根幹である
5. ナレッジグラフ・クロスリファレンス: Readwise Wikiwise のように、保存記事間の関連性を AI が自動検出・可視化する動向が出現した
6. 音声化・マルチモーダル: Daily Reviews の音声化や YouTube 文字起こし要約など、テキスト以外への対応が進んでいる

## 新機能提案

### 🏆 優先度: High（すぐに着手すべき）

#### 提案 1: AI チャットアシスタント（記事との対話）

- 概要: 記事詳細ページにチャットサイドバーを追加し、保存した記事の内容について質問応答できる機能である。Readwise Ghostreader Chat に相当する
- ユーザー価値: 記事を「読む」だけでなく「対話する」体験を提供する。「この記事の主要な論点」「この技術の利点と欠点」のような質問に AI が記事コンテンツを踏まえて回答する。2026 年の競合が標準的に提供しており、不在は大きなギャップである
- 実装難易度: Medium
- 技術的アプローチ:
  - D1 に `chat_messages` テーブルを追加する（id・articleId・role・content・createdAt）
  - ドメイン層に `ArticleChatAssistant` ドメインサービスインターフェースを追加する
  - インフラ層に `WorkersAiChatAssistant` を実装する。既存の Cloudflare AI binding を活用する
  - 記事 content をシステムプロンプトのコンテキストとして渡す
  - アプリケーション層に `sendChatMessage` コマンドと `ChatQueryService` を追加する
  - フロントエンドの `ArticleDetailPage.vue` にスライドアウト型チャットパネルを追加する
  - ハイライトテキストを選択して「これについて質問」するショートカットを提供する
- 参考: [Readwise Ghostreader Chat](https://docs.readwise.io/reader/guides/ghostreader/chat), [Obsidian AI Interpreter](https://obsidian.md/clipper)

#### 提案 2: ブラウザ拡張（Chrome Extension）

- 概要: Chrome 拡張機能を開発し、閲覧中のページをワンクリックでクリッピングする。選択テキストからのハイライト保存や右クリックメニュー保存にも対応する
- ユーザー価値: 現在は Web UI から URL を手動入力する必要がある。ブラウザ拡張により閲覧フローを中断せずに記事を保存できる。全主要競合が提供しており、不在は致命的なギャップである
- 実装難易度: Medium
- 技術的アプローチ:
  - `packages/extension` として monorepo に追加する。Chrome Extension Manifest V3 を採用する
  - Popup UI は Vue 3 + UnoCSS で構築する（既存スタック統一）
  - `@web-clipper/shared` の Zod スキーマを拡張側でも再利用し型安全性を確保する
  - Content Script でページメタデータ・選択テキストを取得する
  - 既存の `POST /api/articles` エンドポイントをそのまま利用する
  - API トークン認証を追加する（`POST /api/auth/token` で発行、`Authorization: Bearer` で認証）
  - 右クリックコンテキストメニュー「web-clipper に保存」を追加する
  - 選択テキストがある場合はハイライトとして `POST /api/articles/{id}/highlights` も同時に呼び出す
- 参考: [Obsidian Web Clipper (GitHub)](https://github.com/obsidianmd/obsidian-clipper), [Auto Web Clipper](https://chromewebstore.google.com/detail/auto-web-clipper/cpoccbefjhofopchjofhdlghdihklfmn)

### 📋 優先度: Medium（次のマイルストーンで検討）

#### 提案 3: セマンティック検索（ベクトル検索）

- 概要: 記事コンテンツのベクトル埋め込みを生成し、自然言語による意味的な検索を可能にする
- ユーザー価値: React のパフォーマンス最適化のように、キーワードが正確に一致しなくても関連記事を検索できる。記事数が増えるほど価値が高まる
- 実装難易度: Medium
- 技術的アプローチ:
  - Cloudflare Vectorize（ベクトルデータベース）を D1 と併用する
  - Cloudflare AI の埋め込みモデル（`@cf/baai/bge-base-en-v1.5`）で記事テキストをベクトル化する
  - `clipArticle` コマンド実行後にバックグラウンドで埋め込み生成・保存する（`waitUntil` パターン活用）
  - 検索 API に `semanticQuery` パラメータを追加し、既存のキーワード検索と併用可能にする
  - ドメイン層に `ArticleEmbeddingService` インターフェースを追加する
- 参考: [Cloudflare Vectorize](https://developers.cloudflare.com/vectorize/), [Remio AI スマート検索](https://www.remio.ai/)

#### 提案 4: 要約スタイルの多様化

- 概要: 現在の単一要約に加え、複数の要約形式を選択可能にする。1-2 行の TL;DR、箇条書きキーポイント、詳細要約の 3 種類を提供する
- ユーザー価値: 一覧で素早く内容を把握したい場合は TL;DR、じっくり理解したい場合は詳細要約を使い分けられる
- 実装難易度: Low
- 技術的アプローチ:
  - `SummaryStyle` 値オブジェクトを追加する（tldr, keyPoints, detailed）
  - `generateSummary` コマンドに `style` パラメータを追加する
  - `WorkersAiSummarizer` のプロンプトをスタイルごとに切り替える
  - D1 の `articles` テーブルに `aiSummaryKeyPoints` カラムを追加する
  - フロントエンドの記事詳細ページに要約スタイル切替 UI を追加する
- 参考: [Readwise Ghostreader 要約オプション](https://docs.readwise.io/reader/guides/ghostreader/overview)

#### 提案 5: エクスポート機能（Markdown / JSON）

- 概要: 保存記事・ハイライト・タグを Markdown ファイルまたは構造化 JSON として一括エクスポートする
- ユーザー価値: データポータビリティを保証し、Obsidian Vault への直接インポートや他ツールへの移行を可能にする。自分のデータを自分で管理できることは信頼の基盤となる
- 実装難易度: Low
- 技術的アプローチ:
  - アプリケーション層に `ExportService` を追加する（`exportAllAsMarkdown`, `exportAllAsJson`）
  - `GET /api/export/markdown` で ZIP ファイルを返す（1 記事 = 1 Markdown ファイル、フロントマター付き）
  - `GET /api/export/json` で全データの構造化 JSON を返す
  - ハイライトは Markdown 内に `==ハイライトテキスト==` 形式で埋め込む（Obsidian 互換）
  - フロントエンドの設定画面にエクスポートボタンを追加する
- 参考: [Obsidian Markdown 形式](https://obsidian.md/), [Readwise エクスポート](https://readwise.io/export)

### 🔭 優先度: Low（長期的に検討）

#### 提案 6: RSS フィード購読

- RSS フィード URL を登録し、Cloudflare Workers Cron Trigger で定期的に新着記事を自動クリッピングする
- D1 に `feeds` テーブルを追加し、`Feed` 集約を新設する
- 既存の `clipArticle` コマンドを再利用して自動保存のパイプラインを構築する

#### 提案 7: AI クロスリファレンス（関連記事の自動発見）

- 新規記事クリッピング時に、既存ライブラリ内の関連記事を AI が自動検出し、リンクを提案する
- セマンティック検索（提案 3）のインフラを活用し、類似度の高い記事を表示する
- Readwise Wikiwise のようなナレッジグラフの初歩的な実装となる

#### 提案 8: スペースドリピティション（復習システム）

- 保存したハイライトを最適な間隔で再表示し、知識の定着を促進する
- ダッシュボードに「今日の復習」セクションを追加する（SM-2 アルゴリズムベース）
- Readwise の Daily Review に相当する機能であり、クリッピングツールを知識管理ツールへ進化させる

### 設計上の注意点

- AI チャット: チャット履歴は `Article` 集約に含めず、`articleId` の ID 参照で独立管理する。チャットの増大が記事の読み込みパフォーマンスへ影響しない設計とする
- セマンティック検索: ベクトル埋め込みの生成は非同期バックグラウンドタスクとして実行する。既存の `waitUntil` パターン（AI 要約・自動タグ付けで確立済み）を踏襲する
- API トークン認証: ブラウザ拡張向けのトークンベース認証は、既存の Cookie セッション認証と共存させる。認証ミドルウェアで両方式を判定する設計にする
- neverthrow パターンの継続: 新規コマンド・サービスは全て `ResultAsync` を返す既存パターンを厳守する
