# web-clipper 新機能提案 - 2026-06-01

## エグゼクティブサマリー

前回提案（2026-04-01）から 2 ヶ月で AI 自動タグ付けとハイライト機能が実装完了しました。2026 年 6 月時点の競合分析では、AI チャットアシスタント・YouTube 文字起こし・ブラウザ拡張が差別化の鍵となっています。本提案ではブラウザ拡張と AI チャット機能を最優先とし、計 8 機能を提案します。

## 現状の機能セット

- 記事クリッピング — URL からメタデータ（OGP 等）を自動抽出し Markdown 形式で本文を保存する
- AI 要約生成 — Cloudflare AI による記事要約を生成する
- AI 自動タグ付け 🆕 — クリッピング時に AI が既存タグから最適なタグを自動提案・適用する
- ハイライト・アノテーション 🆕 — 記事本文内のテキスト選択で色分けハイライトとメモを保存する
- タグ管理 — カスタムタグによる記事分類に対応する（多対多リレーション）
- 検索・フィルタ — タイトルや説明文の検索、ソース・タグ・既読状態のフィルタに対応する
- ソース自動分類 — Twitter や Qiita、Zenn、GitHub など 11 種のソースを自動判別する
- 認証 — ユーザー名/パスワードと GitHub OAuth に対応する
- PWA 対応 — Web Share Target API による OS 共有メニューからの記事追加に対応する
- ダーク/ライトモード — テーマ切り替えと永続化に対応する
- API ドキュメント — OpenAPI 仕様と Scalar UI リファレンスを提供する

## 新機能提案

### 🏆 優先度: High（すぐに着手すべき）

#### 提案 1: ブラウザ拡張（Chrome Extension）

閲覧中のページをワンクリックでクリッピングする Chrome 拡張機能を開発します。選択テキストからのハイライト保存や右クリックメニューからの保存にも対応します。

全主要競合が提供する UX の根幹機能です。現在は Web UI を開いて URL をペーストする必要があり、閲覧フローの中断が大きいです。ブラウザ拡張により保存の摩擦を削減できます。

実装難易度は Medium です。

##### 技術的アプローチ

- `packages/extension` として monorepo に追加する
- Chrome Extension Manifest V3 + TypeScript で構築する
- Popup UI は Vue 3 で実装し、既存スタックと統一する
- `@web-clipper/shared` の Zod スキーマで API との型安全な通信を保証する
- Content Script でページメタデータと選択テキストを取得する
- 認証は既存 Cookie セッションと API トークン方式のデュアルサポートにする
- `POST /api/articles` と `POST /api/articles/:id/highlights` を利用する
- Vite + CRXJS で拡張のビルドパイプラインを構築する

参考: [Obsidian Web Clipper](https://github.com/obsidianmd/obsidian-clipper)

#### 提案 2: AI チャットアシスタント（記事 Q&A）

保存済み記事に対してチャット形式で質問・深掘りできる AI アシスタント機能を実装します。Readwise の Ghostreader v2 に相当します。

「この記事の主要な論点は何か」「この技術の欠点は何か」といった自然言語の質問に AI が回答します。記事を「読んで終わり」から「対話して理解」に進化させる機能です。Readwise Reader が有料で提供する機能を自前で実現できます。

実装難易度は Medium です。

##### 技術的アプローチ

- ドメイン層に `ArticleAssistant` ドメインサービス IF を追加する
- インフラ層に `WorkersAiArticleAssistant` を実装する
- 記事の Markdown コンテンツをシステムプロンプトのコンテキストとして渡す
- アプリケーション層に `askArticleQuestion` コマンドを追加する
- `POST /api/articles/:id/chat` エンドポイントを新設する
- フロントエンドの記事詳細ページにチャット UI パネルを追加する
- 会話履歴は D1 に `article_chats` テーブルを追加して永続化する
- Streaming Response で逐次レスポンスを返して UX を向上させる

参考: [Readwise Ghostreader](https://readwise.io/read), [Mem AI Web Clipper](https://get.mem.ai/features/web-clipper)

### 📋 優先度: Medium（次のマイルストーンで検討）

#### 提案 3: YouTube 動画クリッピング・文字起こし

YouTube URL を保存する際に自動生成字幕を取得・保存します。トランスクリプトに対してハイライトや AI 要約も適用可能にします。

技術系 YouTube 動画の増加に伴い、動画コンテンツの知識ベース化ニーズが高まっています。Readwise Reader と Obsidian Web Clipper が対応済みの機能です。

実装難易度は Medium です。

##### 技術的アプローチ

- `Source` 値オブジェクトに `youtube` を追加する
- `youtube-transcript` ライブラリでトランスクリプトを取得する
- `ContentExtractor` に YouTube 用の実装を追加する。Strategy パターンを採用する
- 記事の `content` フィールドにタイムスタンプ付き Markdown として保存する
- 既存のハイライト・AI 要約機能をそのまま適用可能にする

参考: [Obsidian Web Clipper YouTube Transcripts](https://digitalbiztalk.com/article/obsidian-web-clipper-s-youtube-transcripts-reader-mode-in-2026)

#### 提案 4: 全文コンテンツ検索の強化

現在の検索はタイトル・説明文のみが対象です。保存済みの記事本文を対象とした全文検索を実装します。ハイライトテキストも検索対象にします。

「あの記事に書いてあったキーワード」を本文から検索できれば、知識ベースとしての価値が向上します。

実装難易度は Low です。

##### 技術的アプローチ

- D1 の `LIKE` 検索で記事本文を対象にする。`content` フィールドは保存済みである
- `ArticleQueryService` に `contentSearch` パラメータを追加する
- 検索結果にマッチ箇所のスニペットを含める
- D1 が FTS5 対応した場合はトークナイズベースの高速検索に切り替える
- ハイライトテキストも検索対象に含める

参考: [Readwise Reader](https://readwise.io/read)

#### 提案 5: TTS（テキスト音声読み上げ）

保存した記事を AI 音声で読み上げる機能を実装します。通勤中や家事中に「聞く読書」を可能にします。

Readwise Reader が Unreal Speech 連携で提供する人気機能です。「読む時間がない」ユーザーに記事消化の新チャネルを提供します。

実装難易度は Medium です。

##### 技術的アプローチ

- Web Speech API を使ってまず MVP を実装する。追加コストはかからない
- 記事詳細ページに再生・一時停止・速度調整の UI を追加する
- Markdown を音声読み上げ向けプレーンテキストに変換するユーティリティを作成する
- 将来的には Cloudflare AI の TTS モデルや外部 API で高品質音声に切り替える

参考: [Readwise Reader TTS](https://www.speedreadinglounge.com/readwise-reader-review)

## DDD / クリーンアーキテクチャ観点のメモ

### 提案機能のレイヤー配置

| 提案 | レイヤー配置 | ドメインモデルへの影響 |
|------|------------|---------------------|
| ブラウザ拡張 | プレゼンテーション層 | なし。API トークン追加時は `ApiToken` 値オブジェクトの新設が必要 |
| AI チャット | ドメインサービス + インフラ層 | `ArticleAssistant` ドメインサービス IF を追加 |
| YouTube 対応 | ドメイン層 + インフラ層 | `Source` に `youtube` を追加。`ContentExtractor` の実装追加 |
| 全文検索強化 | インフラ層 + アプリケーション層 | ドメイン層への変更なし。クエリ拡張のみ |
| TTS | プレゼンテーション層 | ドメイン層への変更なし。フロントエンドの UI 拡張のみ |
| RSS 購読 | 全レイヤー | `Feed` 集約と `FeedRepository` IF を新設 |
| エクスポート | アプリケーション層 + インフラ層 | `ExportService` を追加。ドメイン層への影響は軽微 |
| マルチモデル AI | インフラ層 | ドメインサービス IF は変更不要。DI で切り替え |

### 設計上の注意点

AI チャットの会話履歴を永続化する場合は `ChatSession` を独立集約にします。`ArticleId` を ID 参照で持たせ、`Article` 集約の肥大化を防ぐ設計が望ましいです。

YouTube 対応では `ContentExtractor` に Strategy パターンを適用します。URL パターンに応じて `YoutubeContentExtractor` と `ReadabilityContentExtractor` を切り替えます。

マルチモデル AI は `ArticleSummarizer` と `TagSuggester` が既に抽象化されています。インフラ層に新実装を追加し、`createDeps()` で切り替えるだけで対応できます。

全文検索は D1 の `content` フィールドが既に存在するため、クエリ側の変更のみで実現できます。最もコストパフォーマンスの高い改善項目です。
