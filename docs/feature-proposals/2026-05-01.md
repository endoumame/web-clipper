# web-clipper 新機能提案 - 2026-05-01

## エグゼクティブサマリー

Pocket（2025 年 7 月終了）と Omnivore（2024 年 11 月終了）の相次ぐサービス終了により、大量のユーザーが移行先を探している。本プロジェクトは Clean Architecture・Cloudflare Workers AI・D1 という堅実なスタックを持ち、この市場機会を捉える好位置にある。ブラウザ拡張機能の開発とデータポータビリティの強化を最優先とし、AI チャット機能やテンプレートシステムで競合との差別化を図る。

## 現状の機能セット

- URL 入力による記事保存と、OG タグ・タイトル・説明文の自動抽出
- Mozilla Readability + LinkedOM による本文抽出と、Turndown による Markdown 変換
- Cloudflare Workers AI（llama-3.1-8b-instruct）によるワンクリック AI 要約
- 記事クリッピング時にバックグラウンドで動作する AI 自動タグ付け
- カラー選択・前後コンテキスト保存・ノート注釈に対応したテキストハイライト
- 多対多のタグ分類、人気タグ表示、検索ボックス統合フィルタ
- 記事タイトル・説明文・メモを横断する全文検索
- Twitter・Qiita・Zenn・GitHub 等 11 種以上のソース自動分類
- 記事の既読・未読状態トグル
- ユーザー名/パスワードおよび GitHub OAuth による認証
- ダーク/ライトテーマと View Transitions API によるアニメーション
- OpenAPI 3.0 仕様 + Scalar UI による API ドキュメント
- neverthrow による Result 型ベースの統一的エラー処理

## 競合・トレンド分析

### 市場環境の激変

2024-2025 年に Omnivore（ElevenLabs に買収後サービス終了）と Pocket（Mozilla が 2025 年 7 月に終了）が相次いでシャットダウンした。数百万人のユーザーが移行先を探しており、データポータビリティとサービス持続性を重視する傾向が強い。

### AI 統合の最新トレンド

- AI 要約はすでに table stakes（必須機能）化しており、本プロジェクトは対応済み
- AI 自動タグ付けは急速に普及中で、本プロジェクトは対応済み
- ページコンテキスト付き AI チャットが新たな差別化要因として台頭している
- Obsidian Interpreter 方式のテンプレート内 AI 変数は、高度ながらユーザーフレンドリーな UX として注目を集めている

### Cloudflare エコシステムの追い風

- Workers AI の `toMarkdown` は複数フォーマットから Markdown への変換を Workers 上でネイティブ実行できる
- Browser Rendering の `/markdown` エンドポイントは Web ページを取得し Markdown に変換する（SPA 対応）
- Markdown for Agents は HTML を Markdown に変換をエッジで実行し、トークン使用量を最大 80% 削減する

## 新機能提案

### 🏆 優先度: High（すぐに着手すべき）

#### 提案 1: ブラウザ拡張機能（Chrome / Firefox）

現在は Web UI から URL を手入力する必要がある。閲覧中のページからワンクリックでクリッピングできるブラウザ拡張機能を開発する。テキスト選択によるハイライト保存、右クリックメニュー統合、ポップアップ UI でのタグ選択・メモ追加を含む。

クリッピングの摩擦を劇的に削減できるため、ユーザー価値が高い。競合ツールはすべてブラウザ拡張を提供しており、これなしでは採用障壁が高い。Pocket/Omnivore からの移行ユーザーが最初に期待する機能でもある。

実装難易度は Medium。技術的なアプローチは以下の通り。

- Chrome Extension Manifest V3 + Firefox WebExtension API で開発
- `packages/extension` として monorepo に追加
- Content Script でページ内テキスト選択・ハイライトを検出
- Popup UI は Vue 3 + UnoCSS で統一的なデザインを実現
- 既存の `/api/articles` POST エンドポイントを直接利用
- `packages/shared` の型定義を拡張と共有
- Browser Rendering `/markdown` エンドポイントで SPA ページの抽出精度を向上

Obsidian Web Clipper（MIT ライセンス、obsidianmd/obsidian-clipper）や Karakeep Chrome Extension が参考になる。

#### 提案 2: データエクスポート / インポート機能（Pocket・Omnivore 移行対応）

記事・タグ・ハイライトの一括エクスポート（Markdown / JSON）を提供する。また、Pocket・Omnivore・一般的なブックマークファイル（Netscape HTML）からのインポート機能を実装する。

Pocket（2025 年 7 月終了）と Omnivore（2024 年 11 月終了）から移行するユーザーを直接取り込める。データポータビリティはサービス信頼性の証明でもある。「また消えるのでは」という不安を払拭する効果も期待できる。

実装難易度は Medium。技術的なアプローチは以下の通り。

- エクスポートは新規 API エンドポイント `GET /api/export` で対応する。記事を Markdown ファイル群（フロントマター付き）として ZIP で返却する。JSON 一括エクスポートにも対応する
- インポートは `POST /api/import` エンドポイントで対応する。Pocket の HTML エクスポートファイルをパースし、Omnivore の JSON エクスポートを変換する。`linkedom` を活用して Workers 上で HTML パースを実行する
- ユースケース層に `ExportArticlesCommand` / `ImportArticlesCommand` を追加する
- ドメイン層に `ImportSource` 値オブジェクトを追加し、インポート元を追跡する
- Web UI に設定画面を追加し、ファイルアップロードと進捗表示を提供する

Readwise の Omnivore インポートツールや Raindrop.io の Pocket インポート機能が参考になる。

### 📋 優先度: Medium（次のマイルストーンで検討）

#### 提案 3: マルチモデル AI 対応（OpenRouter / Ollama / 各社 API）

現在 Cloudflare Workers AI（llama-3.1-8b-instruct）に固定されている AI 機能を拡張する。ユーザーが任意の LLM プロバイダ（OpenAI・Anthropic・Google Gemini・Ollama ローカル）を選択できるようにする。

より高品質な要約・タグ提案が可能になる。プライバシー重視ユーザーは Ollama でローカル実行できる。Obsidian Web Clipper が OpenRouter 対応で高い評価を得ている。

実装難易度は Medium。技術的なアプローチは以下の通り。

- ドメインサービス `ArticleSummarizer` / `TagSuggester` のインターフェースはそのまま活用できる（Clean Architecture の恩恵）
- インフラ層に `OpenAISummarizer` や `AnthropicSummarizer` 等の実装を追加する
- `users` テーブルに `aiConfig` JSON カラムを追加し、プロバイダ・API キー・モデル名を保存する
- Web UI の設定画面に AI プロバイダ設定フォームを追加する
- API キーは D1 に暗号化保存する（Web Crypto API で AES-GCM を使用）

Obsidian Interpreter のマルチプロバイダ対応や Karakeep の OpenAI/Anthropic/Ollama サポートが参考になる。

#### 提案 4: 記事コンテキスト付き AI チャット

記事詳細画面にサイドバー型の AI チャット機能を追加する。記事の全文をコンテキストとして、要約・質問応答・用語解説・翻訳などを自然言語で依頼できる。

長文記事の理解を加速し、能動的な学習を支援する。Readwise Reader の Ghostreader が高い評価を受けている機能カテゴリでもある。

実装難易度は Medium。技術的なアプローチは以下の通り。

- 新規 API エンドポイント `POST /api/articles/:id/chat` を追加する（ストリーミングレスポンス対応）
- 記事の Markdown コンテンツをシステムプロンプトに含め、ユーザーの質問に回答する
- Vue コンポーネント `ArticleChatSidebar.vue` を記事詳細画面に追加する
- Cloudflare Workers AI の streaming 対応を活用する
- 会話履歴はクライアントサイドで保持する（セッション単位で、永続化は不要）

Readwise Ghostreader や Web Highlights の AI チャット機能が参考になる。

#### 提案 5: クリッピングテンプレートシステム

サイトごとに抽出ルールをカスタマイズできるテンプレートシステムを導入する。CSS セレクタ・メタタグ・AI プロンプトを変数として組み合わせ、構造化されたクリッピングを可能にする。

技術ブログの著者情報やレシピサイトの材料リストなど、サイト種別に応じた最適な抽出が可能になる。Obsidian Web Clipper の Interpreter が証明した高い需要がある。

実装難易度は High。技術的なアプローチは以下の通り。

- `templates` テーブルを D1 に追加する（`id`・`name`・`urlPattern`・`extractionRules` JSON・`aiPrompts` JSON）
- ドメインエンティティ `ClippingTemplate` を追加する（URL パターンマッチングと変数展開ロジック）
- `ContentExtractor` インターフェースを拡張し、テンプレート適用をサポートする
- Web UI にテンプレート管理画面を追加する
- デフォルトテンプレート（汎用・ブログ・ニュース・レシピ・論文）をシードデータとして提供する

Obsidian Web Clipper の 5 種変数型（Preset / Prompt / Selector / Meta / Schema.org）が参考になる。

### 🔭 優先度: Low（長期的に検討）

#### 提案 6: RSS / ニュースレターインボックス統合

- RSS フィード購読と専用メールアドレスによるニュースレター受信を統合し、記事の統一的な閲覧体験を提供する
- Cloudflare Email Workers で受信メールを処理し、D1 に記事として保存する
- Readwise Reader の「すべてを一箇所で読む」体験に相当する

#### 提案 7: ブラウザ上の永続ハイライト

- ブラウザ拡張機能と連携し、過去にハイライトしたページを再訪問した際にハイライトを復元表示する
- Content Script で DOM にハイライトを注入する。`prefixContext` / `suffixContext` を活用した位置復元を行う
- Web Highlights（Chrome Web Store 評価 4.83）の中核機能に相当する

#### 提案 8: YouTube / 動画トランスクリプトクリッピング

- YouTube 動画 URL からトランスクリプト（字幕テキスト）を抽出し、記事として保存する
- タイムスタンプ付きハイライトで動画内の特定箇所を参照可能にする
- Workers AI の音声認識（Whisper）を活用した字幕なし動画への対応も将来的に検討する

## DDD / クリーンアーキテクチャ観点のメモ

### ドメイン層への影響

提案 1（ブラウザ拡張）はドメイン層への変更が不要であり、既存の `Article`・`Highlight` 集約をそのまま利用する。新規パッケージ `packages/extension` はインターフェースアダプタ層の追加に相当する。

提案 2（エクスポート/インポート）では `ImportSource` 値オブジェクトを追加し、`ArticleRepository` に一括操作メソッドを追加する。ユースケース層に `ExportArticlesQuery` / `ImportArticlesCommand` を追加する。

提案 3（マルチモデル AI）ではドメインサービスインターフェース（`ArticleSummarizer`・`TagSuggester`）の変更が不要となる。Clean Architecture の利点を活かせる場面です。インフラ層に新規実装を追加し、`AiConfig` 値オブジェクトをドメイン層に追加する。

提案 4（AI チャット）では新規ドメインサービス `ArticleAssistant` インターフェースを追加する。チャットのステートレス性を活かし、集約への永続化は不要となる。

提案 5（テンプレート）では新規集約 `ClippingTemplate` を追加する。`ContentExtractor` ドメインサービスを拡張し、URL パターンマッチングは値オブジェクトとして設計する。

### レイヤー配置

| 提案 | ドメイン層 | ユースケース層 | アダプタ層 | インフラ層 |
|---|---|---|---|---|
| ブラウザ拡張 | - | - | Extension UI・Content Script | Chrome/Firefox API |
| エクスポート/インポート | ImportSource VO | ExportQuery・ImportCommand | API エンドポイント | ZIP 生成・HTML パーサ |
| マルチモデル AI | AiConfig VO | - | API エンドポイント（設定） | 各プロバイダ実装 |
| AI チャット | ArticleAssistant IF | ChatWithArticle UC | API・Vue コンポーネント | Workers AI Streaming |
| テンプレート | ClippingTemplate 集約 | ApplyTemplate UC | API・Vue 管理画面 | D1 リポジトリ |
