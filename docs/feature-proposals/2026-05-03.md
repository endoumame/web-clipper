# web-clipper 新機能提案 - 2026-05-03

## エグゼクティブサマリー

前回提案（2026-04-01）以降、AI 自動タグ付けとハイライト・アノテーション機能が実装されました。2026 年 Q2 の競合動向では、セマンティック検索・AI チャット・ブラウザ拡張がユーザー獲得の鍵となっています。本提案では、ブラウザ拡張の開発と、セマンティック検索・AI チャットなど差別化に繋がる 8 つの機能を提案します。

## 現状の機能セット

- 記事クリッピング: URL からメタデータ + 本文を自動抽出し保存する（Readability + Markdown 変換）
- AI 要約生成: Cloudflare Workers AI（Llama 3.1 8B）による記事要約を生成する
- AI 自動タグ付け: 記事クリップ時に既存タグから最適なタグを自動提案・適用する
- ハイライト・アノテーション: 記事本文内のテキスト選択からハイライト保存する（色・メモ付き）
- タグ管理: カスタムタグによる記事分類（多対多リレーション）
- 検索・フィルタ: タイトル/説明文のテキスト検索、ソース・タグ・既読状態フィルタを提供する
- ソース自動分類: Twitter / Qiita / Zenn / GitHub など 11 種に対応する
- 認証: ユーザー名/パスワード + GitHub OAuth、Cookie ベースセッション管理をサポートする
- ダーク/ライトモード: テーマ切り替えと永続化に対応する
- View Transitions: ページ遷移アニメーションを搭載する
- API ドキュメント: OpenAPI 3.0.0 + Scalar UI を提供する
- エラーハンドリング: neverthrow（Result/ResultAsync）による型安全なエラー処理を採用する

## 新機能提案

### 🏆 優先度: High（すぐに着手すべき）

#### 提案 1: ブラウザ拡張（Chrome Extension）

Chrome 拡張機能を開発し、閲覧中のページをワンクリックでクリッピングします。ページ上でのテキスト選択からのハイライト保存にも対応します。

現在の「Web UI で URL を手入力」というフローは、競合に対して最大の UX ギャップです。全主要競合が拡張を提供しており、これなくしてユーザー獲得は難しいです。ページ上ハイライトとの連携により、既存ハイライト機能の価値も倍増します。

実装難易度は Medium です。

以下が技術的アプローチです。

- `packages/extension` として monorepo に追加する。Manifest V3 + Vue 3 Popup を採用する。
- Content Script でページメタデータと選択テキストを取得する。
- `@web-clipper/shared` の Zod スキーマを拡張側で再利用し、型安全性を確保する。
- 認証は API トークン方式を新設する（Cookie セッションには cross-origin 制約がある）。
- 既存の `POST /api/articles` と `POST /api/articles/:id/highlights` をそのまま利用する。
- WXT フレームワークの採用を検討する（Vite ベースで既存スタックと親和性が高い）。

参考: Obsidian Web Clipper（GitHub 公開）、WXT フレームワーク。

#### 提案 2: セマンティック検索（ベクトル検索）

記事本文の Embedding を生成し、自然言語による意味ベースの検索を実現します。「React のパフォーマンス最適化について書いてあった記事」のような曖昧な検索が可能になります。

現在のテキスト検索はタイトルと説明文の LIKE 検索のみです。「あの記事なんだっけ」という再発見ニーズには応えられません。記事が増えるほど検索の重要性は増します。remio 等の新興ツールが差別化ポイントとして実装しています。

実装難易度は Medium です。

以下が技術的アプローチです。

- Cloudflare Workers AI の Text Embedding モデルを利用する（`@cf/baai/bge-base-en-v1.5` 等）。
- Cloudflare Vectorize へ Embedding を保存する。
- 記事クリップ時に `waitUntil` で Embedding を非同期生成する（既存 AI タグ付けと同パターン）。
- ドメイン層に `ArticleSearchService` インターフェースを追加する。
- インフラ層に `VectorizeArticleSearchService` を実装する。
- 検索 API に `semantic=true` クエリパラメータを追加し、従来のテキスト検索と切り替え可能にする。

参考: Cloudflare Vectorize ドキュメント、remio のニューラル検索。

### 📋 優先度: Medium（次のマイルストーンで検討）

#### 提案 3: AI チャットアシスタント（記事 Q&A）

記事詳細ページにチャット UI を追加し、保存記事の内容について AI に質問できる機能を実装します。記事の主張の根拠や技術の代替手段などについて回答します。

Readwise の Ghostreader と Raindrop.io の Stella が実装済みです。記事の深い理解を支援し、単なる保存ツールから知識管理ツールへの進化を促します。

実装難易度は Medium です。

以下が技術的アプローチです。

- Cloudflare Workers AI の LLM へ記事本文をコンテキストとして渡す。
- `POST /api/articles/:id/chat` エンドポイントを新設する（SSE で逐次応答）。
- `ArticleDetailPage.vue` にチャットサイドパネルを追加する。
- 会話履歴はセッション内のみ保持する（D1 への永続化は不要）。
- ドメイン層に `ArticleAssistant` ドメインサービスインターフェースを追加する。

参考: Readwise Ghostreader、Raindrop.io Stella。

#### 提案 4: Daily Review（復習・再発見機能）

過去に保存・ハイライトした記事を間隔反復アルゴリズムで日次提示します。「今日の振り返り」ページを追加します。

「保存して忘れる」問題はクリッピングツール共通の課題です。Readwise の Daily Review は最も評価の高い機能であり、ハイライト機能と組み合わせると重要箇所の定期的な復習が可能になります。

実装難易度は Low です。

以下が技術的アプローチです。

- `GET /api/articles/daily-review` エンドポイントを新設する。
- 未読やハイライト付きの記事、最近アクセスしていない記事を条件付きランダム取得する。
- Cloudflare Workers の Cron Trigger で日次通知する（将来的に Web Push 対応）。
- フロントエンドに `/review` ページを追加する（カード形式で記事 + ハイライトを表示）。
- `articles` テーブルに `last_reviewed_at` カラムを追加する。

参考: Readwise Daily Review。

#### 提案 5: エクスポート機能（Markdown / JSON）

保存記事を Markdown / JSON / CSV 形式で一括エクスポートします。Obsidian Vault への連携も検討します。

データポータビリティはユーザーの信頼獲得に直結します。ロックイン回避の安心感が導入障壁を下げ、Obsidian ユーザーへのアピールポイントになります。

実装難易度は Low です。

以下が技術的アプローチです。

- `GET /api/articles/export` エンドポイントを新設する。
- 記事本文 + メタデータ + ハイライト + タグを統合した Markdown を生成する。
- 記事数が多い場合は Zip ストリームでレスポンスする。
- アプリケーション層に `ExportArticlesQuery` を追加する。
- フロントエンドにエクスポートボタンを配置する。

参考: Obsidian Web Clipper の Markdown エクスポート形式。

### 🔭 優先度: Low（長期的に検討）

#### 提案 6: RSS / ニュースレター購読

- フィード URL を登録し、Cron Trigger で定期的に新着記事を自動クリップする
- `Feed` 集約を新設し、`clipArticle` コマンドを再利用する

#### 提案 7: マルチメディア対応（YouTube / PDF）

- YouTube URL から動画メタデータと字幕を自動取得・保存する
- PDF のテキスト抽出を Cloudflare Workers AI の OCR 機能で実現する
- `Source` 値オブジェクトに `youtube` / `pdf` を追加する

#### 提案 8: コラボレーション・共有機能

- 記事コレクションの公開リンク生成（読み取り専用共有）を実装する
- チームワークスペースとして複数ユーザーでの記事共有・タグ共有を提供する
- `users` テーブルに `team_id` を追加し、チーム単位のアクセス制御を実装する

### 設計上の注意点

セマンティック検索では、Embedding 生成はインフラ層の関心事として扱います。ドメイン層はスコア付き検索結果の型のみ定義します。Vectorize バインディングは `WorkersVectorizeSearchService` に閉じ込めます。

ブラウザ拡張用の API トークン認証は、既存の Cookie セッション認証と並立させます。`AuthenticationService` ドメインサービスを抽象化し、認証方式の差し替えを可能にします。

AI チャットはステートレスな Q&A として実装します。会話履歴のドメインモデル化は不要であり、フロントエンド側で保持します。
